# Changelog

## Unreleased

- Add a time frame, 1 page, 1 query, and a comparison of 2 periods or 2 pages to `get_seo_data`.
- A source that cannot apply a parameter now reports status `unsupported` and does not run.
- Add the `query_api` tool: 1 official read query for Search Console, GA4, PageSpeed, the Chrome UX Report, Bing, and Clarity, with a list of valid fields and values.
- Add Clarity session recording lists and dashboard questions through the endpoints of the official Clarity MCP server.
- Count each live Clarity call in a daily ledger, and let parallel server processes wait for 1 fetch of the same answer.
- Check each Clarity recording filter value before a call spends quota, and list the valid values, the URL operators, and the units in `query_api`.
- Show the question that Clarity answered in `dashboard_query`, and label `recordings` as a sample.
- Add `task` to `query_api`: an agent asks for a thing such as dead clicks, and gets the exact calls, the fields, and the meaning for each provider, with no network call.
- Fix the Bing methods that take a URL: the API refused the URL in quotes with HTTP 400.
- Fix the Clarity cache key: it holds the project, so a changed `clarity_project` cannot read the answer of the old project.
- Show quota with no network call in `list_sites` and `query_api` discovery: the used count, the limit, and what is left, with the published limits and doc links of each API.
- Show `calls_used_today`, `daily_limit`, `calls_left`, and the reset time in each answer that spends quota, also in a failure. Add `quota_warning` when few calls are left.
- Count URL Inspection calls in a daily ledger, and read the real GA4 token quota from each report.
- Stop the day when the Clarity Data Export API answers HTTP 429.
- Add a rule to the Clarity click tasks: when the dashboard count is 0, do not call `recordings`.
- List in the README what each dashboard shows and the API does not give.
- Fix the call ledgers: a day that is not a real date, or is after today, now fails closed as a broken ledger. It restarted the count before.
- Stop a second Clarity call after a failure: a waiter or a repeat of a request that can have reached the API gets the same failure for 60 seconds and spends nothing.
- Fix a bad HTTP 200 answer of Clarity: the server checks the shape before it saves an answer, so a source no longer fails with `AttributeError` until the next UTC day. The reason says what happened.
- Add a 2 second limit to the ledger lock: a stuck process no longer freezes all sources, and a metered call that cannot get the lock sends nothing.
- Share identical requests of all sources and methods: parallel agents send 1 live call, and a saved answer serves repeats for 5 minutes (30 seconds for a GA4 realtime report). Each answer shows `from_cache`, `cached_at`, `cache_age_seconds`, and `cache_expires_at`.
- Extend the failure window of 60 seconds and the shape check to all sources and methods.
- Trim the outer spaces of a Clarity dashboard question, so that they do not spend a new call.
- Fix the reason of a connection failure: it read `The connection failed. from the API.`
- Give the used count, the limit, and the reset time in each refusal of a call ledger.
- Extend the failure window of 60 seconds to a connection failure of a counted call: a network outage no longer spends the Clarity count of the day with immediate retries.
- Fix a bad HTTP 200 answer of URL Inspection in `index_status`: the source failed with `AttributeError`, and a repeat spent the URLs again. Now the URL fails with a clear reason, the batch waits for its other URLs, and a repeat inside 60 seconds spends nothing.
- Fix a false success of `index_status`: a URL Inspection reply with no `inspectionResult`, such as `{"message": "try later"}`, is now a failure of a wrong shape. It is not saved, and the same request waits 60 seconds. `canonical_match` is `null` when neither side names a canonical. It was `true` before.
- Fix a false success of `query_api` `url_inspection`: a reply whose `inspectionResult` is not an object showed status `ok`, and the server saved it. It is now a failure of a wrong shape. It is not saved, and a repeat inside 60 seconds sends nothing.
- Name each API with 1 line in the `query_api` tool text, so that an agent goes direct to `query_api(api="<name>")` with no discovery call.
- Fix a false empty result of Search Console reads: an HTTP 200 reply that holds no documented field, such as `{"message": "try later"}`, is now a failure of a wrong shape in `search_queries`, `search_pages`, `quick_wins`, `sitemaps`, and the `query_api` methods `search_analytics` and `sitemaps`. It is not saved, and a repeat inside 60 seconds sends nothing. A real empty answer stays `ok`.
- Fix a false mismatch of `index_status`: `canonical_match` is now `null` when 1 side names no canonical, such as a page with no declared canonical. `false` now means that both sides name different canonicals.
- List the standard GA4 dimensions and metrics in `query_api(api="ga4")`, from the official API schema docs, so that an agent needs no `metadata` request for a standard name. `metadata` stays for custom names and for a name that the list does not hold.
- Add `coverage` to each dated result of Search Console and GA4: the real dates of the request, `last_complete_day` and how the server knows it, and `partial_days`. A day up to `last_complete_day` with no rows is a real 0. A later day is partial, and it is not a drop.
- Fix a default range that moved with the hour: Search Console read today in UTC, so a query changed its dates late in the Pacific day. A Search Console day is now a day of PST, as the docs state.
- Change the default GA4 range to end 3 days before today, so that it ends on a complete day. It ended yesterday. `last_days` keeps its length.
- Send `dataState` `all` for a `get_seo_data` Search Console range that passes the fixed end, so that the partial days keep their data. The server sends 1 extra read for each site, shared for 5 minutes, because the docs give `firstIncompleteDate` no other way.
